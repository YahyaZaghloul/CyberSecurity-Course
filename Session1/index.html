Foundations

What is Information Security?

// The CIA Triad

Security is the process of managing risk to critical assets while preserving functionality:

Confidentiality: Data is protected from unauthorized disclosure. (Encryption, ACLs).
Integrity: Data is preserved against unauthorized tampering or modification. (Hashes, signatures).
Availability: Systems and data remain operational and accessible when needed. (Redundancy, resilience).

// The Risk Model

security_equation.txt

Risk = Threat × Vulnerability × Impact

Vulnerability: A security weakness or bug in software, configuration, or human protocol.

Threat Actor: The entity possessing the intent and capability to target that weakness.

Exploit: The method or code used to trigger the vulnerability for unauthorized gain.

Offensive vs. Defensive Security

Red Team / Offensive

Simulate real-world adversary behavior to discover exposure before hostile actors do.

  • Penetration Testing & Red Teaming
  • Web & API Vulnerability Research
  • Privilege Escalation & Lateral Movement
  • Exploit Scripting & Security Tooling

Monitor, detect, analyze, and neutralize active threats across enterprise environments.

  • Security Operations Center (SOC) & SIEM
  • Digital Forensics & Incident Response (DFIR)
  • Threat Hunting & Detection Engineering

Axiom: You cannot defend what you don't know how to break, and you cannot break what you don't understand how to build.
Operating Systems

Why Linux is the Hacker's Operating System

Low-Level System Control

Raw socket craft, packet injection, and direct memory & process manipulation without OS abstraction layers blocking access.

Full Source Transparency

Zero black-box logic. Every system call, kernel module, and network driver is open, readable, and completely customizable.

Servers & Cloud Reality

Over 96% of enterprise cloud workloads, production web servers, firewalls, and IoT devices run Linux. It is both the defensive bastion and primary target.

In security, GUIs hide essential diagnostic details. The Command Line Interface (CLI) gives you precision, speed, and automation.
Systems Architecture

What is an Operating System?

An Operating System manages computer hardware resources and arbitrates requests between programs and physical silicon.

USER SPACE: Applications & CLI Browser, Bash, Python, Nmap, SSH Client
System Calls (`open`, `read`, `write`, `socket`)
KERNEL SPACE: The Operating System Core Process Scheduler, Memory Manager, Virtual File System, Network Stack
Device Drivers
PHYSICAL HARDWARE CPU (x86_64/ARM), RAM, NVMe/SATA Disks, Network Interface (NIC)

User applications never touch hardware directly. They interact strictly via Kernel System Calls.

Core Mechanics

Kernel Space, User Space & The Shell

// Privilege Separation (Rings)

CPUs enforce privilege levels: Ring 0 (Kernel Space) has unlimited hardware control. Ring 3 (User Space) runs isolated user processes.

Bash: Bourne-Again Shell; standard default CLI across Linux distros.

Zsh: Modern shell with rich completion; standard on Kali Linux & macOS.

shell_repl_cycle.txt

> Read-Eval-Print Loop (REPL):

1. Read: Reads the text command entered by user.

2. Parse: Splits into command name, options, and arguments.

3. Path Lookup: Searches directories listed in $PATH.

4. Fork & Exec: Spawns a child process and invokes system calls.

5. Return: Emits output and delivers an exit status code ($?).

Filesystem

Linux Filesystem Hierarchy Standard (FHS)

Unix Philosophy: "Everything is a file" — disks, sockets, running processes, and configuration are all represented in the filesystem tree.
/ (Root)

The top-level root directory of the entire filesystem.

/bin & /usr/bin

Essential user command binaries (ls, cat, bash).

/etc

System-wide configuration files (passwd, shadow, hosts).

/home & /root

Standard user homes (/home/kali) & superuser home (/root).

/var/log

Dynamic system records, auth logs, syslog, and service logs.

/tmp

Temporary scratch directory; world-writable by default.

/dev

Device files mapping disks (/dev/sda, /dev/urandom).

/proc

Pseudo-filesystem reflecting live kernel memory and active processes.

/sbin

System administrative binaries reserved for root (iptables, fdisk).

Security Model

Linux Permissions & Ownership Model

// Dissecting Permissions

ls -la breakdown

- rwx r-x r-- 1 root root 4096 Sep 12 secret.txt

├── [-] File Type (- = file, d = directory, l = symlink)

├── [rwx] Owner permissions (Read, Write, Execute)

├── [r-x] Group permissions (Read, Execute)

└── [r--] Others / World permissions (Read only)

root (UID 0): The superuser. Has authority to override all permissions.

// Octal Notation (4 - 2 - 1)

r (Read) = 4

w (Write) = 2

x (Execute) = 1

Sum values per triplet:

755: Owner rwx (7), Group rx (5), Others rx (5)

600: Owner rw- (6), Group --- (0), Others --- (0)

permission_commands
chmod 600 private_key
chown user:group filename

Command Arsenal // Category 2

File & Directory Manipulation

file_operations.sh

touch <file> : Create an empty file or update timestamps

mkdir <dir> : Create a new directory

mkdir -p a/b/c : Create parent directories recursively

cp src dst : Copy a file

cp -r dir1 dir2 : Copy a directory recursively

mv old new : Move or rename files and directories

rm <file> : Remove/delete a file

rm -rf <dir> : Force recursive deletion of a directory (Caution!)

Escaping Filenames Starting with '-'

The argument parser confuses leading hyphens with command flags:

cat ./-filename • rm ./-filename
Filenames with Spaces

Use double quotes or backslash escape characters:

cat "file name.txt" • cat file\ name.txt

Command Arsenal // Category 4

Searching & Locating Assets

find_command_anatomy

find [starting_path] [predicates/filters]

-name "pattern" : Filter by filename (wildcards allowed)

-iname "pattern" : Case-insensitive name filter

-type f : Match regular files only

-type d : Match directories only

-size 1033c : Exact size of 1033 bytes (c=bytes, k=KB, M=MB)

-user <name> : Owned by specific username

-group <name> : Owned by specific group

! -executable : Invert match (NOT executable)

which & whereis

Locate command binaries in your PATH environment:

which python3 • whereis bash
locate / mlocate

Blazing-fast pre-indexed filesystem database search:

locate rockyou.txt
Command Arsenal // Category 5

Standard Streams & I/O Redirection

// The 3 POSIX Standard Streams

FD 0 (stdin): Standard Input (keyboard by default).
FD 1 (stdout): Standard Output (terminal display).
FD 2 (stderr): Standard Error (error diagnostic stream).
redirection_syntax.sh

> file : Overwrite stdout into file

>> file : Append stdout to the end of file

< file : Read stdin from file

2> /dev/null : Discard all error messages into the void

2>&1 : Combine stderr into stdout

When searching large system trees as an unprivileged user, suppress error clutter: find / -type f -name secret 2>/dev/null
Command Arsenal // Category 6

Pipelines & Text Processing

// The Pipe Operator (`|`)

The pipe (|) connects the stdout of one program directly into the stdin of another. Chaining modular tools creates powerful one-line investigative engines.

sort_uniq_pipeline.sh

# Find lines that occur strictly once:

sort data.txt | uniq -u

Note: uniq only checks adjacent lines, so sorting beforehand is required!

grep_and_cut.sh

// grep: Global Regular Expression Print

grep "pattern" file : Find matching lines

grep -i "token" file : Case-insensitive search

grep -n "token" file : Include line numbers

grep -v "token" file : Invert match (show non-matches)

// cut: Extract Delimited Columns

cut -d ":" -f 1 /etc/passwd : Extract usernames
