The Big Paradigm Shift

CMD vs. PowerShell: Dumb Strings vs. Smart Objects

Why did Microsoft invent PowerShell in 2006 when CMD already existed? The secret lies in how data moves through the terminal:

Command Prompt (`cmd.exe`)

Legacy (1987)

A text processor from the MS-DOS era. Commands output **dumb lines of text** (like a paper receipt). If you want specific data, you must manually count characters, slice words, or write fragile regex.

C:\> tasklist ➔ returns an unprogrammable wall of text strings

PowerShell (`powershell.exe`)

Modern (.NET Engine)

Built directly on Microsoft .NET. Commands output **live, interactive objects** (like a smart toy with clickable buttons). You access any property directly with zero text parsing!

PS C:\> (Get-Process lsass).Id ➔ returns 640 as an integer instantly!
🧾 The Paper Receipt vs. Smart Toy Analogy: CMD prints a paper receipt. If you want the total price, you must read line 5 and count 14 spaces. If an update shifts the table by one space, your script breaks! PowerShell hands you a smart toy where you simply ask: $receipt.Total and get the exact number every time!
Operating System Internals

Kernel Architecture: User Space (Ring 3) vs. Kernel Space (Ring 0)

CPUs enforce hardware-level privilege rings to prevent user applications from corrupting physical memory or crashing the machine:

Ring 3: User Space (The Sandbox) Isolated Virtual Memory

What lives here: Everyday apps (Chrome, Discord, Word, cmd.exe, powershell.exe).

Virtual Memory Isolation: Each process gets its own private virtual address space. Discord cannot read Chrome's memory directly without explicit OS debug rights.

Safe Crashes: If Chrome crashes, only Chrome closes. The operating system kernel remains completely untouched!

Ring 0: Kernel Space (The Core Engine) Direct Hardware Control

What lives here: Core OS executive (ntoskrnl.exe), Hardware Abstraction Layer (HAL), and kernel drivers (GPU, network card, antivirus filters).

Unrestricted Power: Direct access to physical memory, CPU registers, and hardware peripherals. No permission checks inside Ring 0!

The Fatal BSOD: A crash here causes a **Blue Screen of Death (BSOD)** to protect hardware from physical damage.

The Syscall Bridge: How Apps Talk to Hardware
1. User App
Calls WriteFile()
2. kernel32.dll
Subsystem API Translation
3. ntdll.dll
Executes SYSCALL instruction
4. ntoskrnl.exe
Ring 0 writes to disk
🛡️ Red Team Vector: Modern malware uses **BYOVD (Bring Your Own Vulnerable Driver)** to drop into Ring 0 and blind EDRs and antivirus solutions from the kernel level!
Filesystem Architecture

The Windows Filesystem (`C:\`) & The 64-Bit Paradox

Unlike Linux's unified root (/), Windows organizes storage into Drive Letters (C:\, D:\) formatted with NTFS (New Technology File System):

C:\Windows\System32 64-Bit Core

The heart of Windows. Contains core 64-bit OS binaries (cmd.exe, powershell.exe, lsass.exe, svchost.exe) and system DLLs.

C:\Windows\SysWOW64 32-Bit Legacy

Stands for "Windows 32-bit On Windows 64-bit". Contains 32-bit binaries and DLLs so legacy software can run on 64-bit Windows.

C:\Program Files Protected

Where 64-bit software installs. (32-bit installs in Program Files (x86)). Protected by strict ACLs—standard users cannot write here without UAC elevation!

C:\Users\<Username> (User Profiles)

Personal user realm: Desktop, Documents, Downloads, and the hidden AppData folder. Standard users have full write access here.

Path Slash Differences

Linux uses forward slashes (/etc/passwd). Windows uses backslashes (C:\Windows\System32). Pro Tip: Modern PowerShell accepts both styles interchangeably!

🤯 The 64-Bit Paradox: Why does System32 hold 64-bit binaries while SysWOW64 holds 32-bit binaries? In the 1990s, legacy software had C:\Windows\System32 hardcoded. When Microsoft transitioned to 64-bit Windows, changing that folder name would have broken thousands of enterprise programs. Microsoft preserved System32 for native (64-bit) files and created SysWOW64 for 32-bit emulation!

Threat Hunting & Forensics

Where Malware Hides & Alternate Data Streams (ADS)

Because standard users cannot write to C:\Windows or C:\Program Files, 90%+ of malware targets these specific unprivileged staging grounds:

AppData\Roaming

Follows user accounts across corporate Active Directory domains. Stores browser sessions, Discord tokens, crypto wallets, and persistence scripts.

Env: %APPDATA%
AppData\Local\Temp

The #1 Dropper Haven! World-writable by standard users AND allows binary execution. Phishing payloads and ransomware unpack here.

Env: %TEMP%
C:\Users\Public

Shared folder accessible by EVERY local and domain account on the machine. Hackers use it as a staging directory for cross-user privilege escalation.

Env: %PUBLIC%
The False-Bottom Drawer: Alternate Data Streams (ADS) Stealth Storage

NTFS allows files to store multiple hidden data streams behind the default stream. Attackers hide executable payloads inside ordinary text files!

# Hide evil.exe behind innocent report.txt:
type payload.exe > report.txt:malware.exe
# Audit & detect hidden streams in PowerShell:
Get-Item report.txt -Stream * (or in CMD: dir /r)
🚨 Incident Response Priority: When investigating a compromised Windows machine, the first 3 directories to inspect are %TEMP%, %APPDATA%, and C:\Users\Public.
Identity & Access Architecture

The SAM Vault & Windows Authentication Pipeline

Where are local user accounts and passwords stored in Windows, and how does the operating system authenticate you?

The SAM Vault C:\Windows\System32\config\SAM

Security Account Manager: The encrypted registry database storing all local user accounts, group memberships, and password hashes.

The Kernel Lock: Locked exclusively by the kernel (SYSTEM account). Even the local Administrator cannot open, copy, or read the SAM file while Windows is running!

NTLM Hashes: Windows NEVER stores plaintext passwords in the SAM! It stores the NTLM hash (MD4(UTF-16LE(password))).

The LSASS Bouncer winlogon → lsass

1. Logon Prompt: winlogon.exe captures user credentials and passes them to the security authority.

2. LSASS Engine: lsass.exe (Local Security Authority Subsystem Service) computes the NTLM hash and compares it to the SAM database.

3. Access Token Minter: If valid, LSASS creates your **Access Token** containing your digital identity (SIDs) and privileges!

// Local Workstation vs. Enterprise Domain Authentication
Local Machine (Standalone):
Auth validated locally against the SAM file (C:\Windows\System32\config\SAM).
Active Directory Domain (Enterprise):
Auth validated over the network by a Domain Controller via Kerberos against NTDS.dit!
🔓 Offensive Vector: Because the kernel locks SAM, attackers extract it using Volume Shadow Copies (vssadmin create shadow /for=C:) to snapshot the locked disk, or dump LSASS memory with Mimikatz.
Security Identifiers & Tokens

Security Identifiers (SIDs) & Access Token Anatomy

Windows does NOT care about your human username. Internally, every account, group, and process is identified by an immutable Security Identifier (SID):

Anatomy of a Security Identifier (SID):
S - 1 - 5 - 21-3623811015-3361044348-30300820 - 500
S-1: SID Prefix & Revision level 1
5: NT Authority identifier
21-...: Unique Machine or Domain ID
500 (RID): Relative Identifier (The Account!)
RID 500 GOD MODE

Built-in Administrator

Always the built-in local Administrator, even if renamed to hide it!

RID 501 DISABLED

Built-in Guest

Default guest account for unauthenticated visitors. Disabled by default.

RID 1000+ USER REALM

Standard & Custom Users

First created user gets RID 1000, next gets 1001, and so forth.

Token Recon Primitives:
whoami /user (View SID) whoami /priv (View Privileges) whoami /groups (View Groups)

The Pipeline

The Object Pipeline & The Conveyor Belt (`$_`)

The pipe (|) sends live objects down a conveyor belt. Instead of writing messy regex to parse strings, you filter and sort structured properties directly:

Pipeline Masterclass: The Core 4 Cmdlets

1. Where-Object (?): The Conveyor Belt Scanner

# Filter processes using more than 100MB of RAM:

Get-Process | Where-Object WS -gt 100MB

# Using the $_ variable ("this specific item on the belt"):

Get-Service | Where-Object { $_.Status -eq 'Running' }

2. Sort-Object (sort): The Organizer

# Sort processes descending by memory consumption:

Get-Process | Sort-Object -Descending WS

3. Select-Object (select): Column Chooser

# Pick specific columns and top 3 rows:

Get-Process | Select-Object -First 3 Name, Id, WS

4. Measure-Object (measure): The Counter

Count lines in a file (like wc -l):
Get-Content auth.log | Measure-Object -Line

Count total files on Desktop:
(Get-ChildItem Desktop).Count

⚙️ Comparison Operators: PowerShell uses text operators: -eq (equal), -ne (not equal), -gt (greater than), -lt (less than), -like (wildcard), and -match (regex).
File Inspection

Reading & Pattern Searching: PowerShell's `grep`

Inspecting log files, hunting credentials in config files, and searching patterns across directories:

Reading Content: Get-Content (cat)

# Read full file contents (like cat / type):

Get-Content C:\Logs\auth.log # or: cat auth.log

# Read first 5 lines (like head -n 5):

Get-Content auth.log -TotalCount 5

# Read last 10 lines (like tail -n 10):

Get-Content auth.log -Tail 10

# Live stream log updates (like tail -f!):

Get-Content auth.log -Tail 10 -Wait

Pattern Searching: findstr vs. Select-String

# In CMD (Legacy):

findstr /i "failed" auth.log

# In PowerShell (PowerShell's grep!):

Select-String -Path auth.log -Pattern "Failed"

# Search across all .txt files recursively:

Select-String -Path *.txt -Pattern "password"

# Pipe Get-Content into Select-String:

Get-Content config.ini | Select-String "api_key"

🔍 Log Monitoring Tip: Get-Content -Wait functions like Linux tail -f, allowing security analysts to watch authentication logs in real-time as brute-force attacks unfold.
Core Windows Engines

Core Windows Engines: What Are Services & The Registry?

Before auditing threat persistence, understand the two invisible internal engines that power how Windows boots, operates, and remembers settings:

1. Windows Services Background Workers
  • What is it? A long-running program that executes headless in the background without a user interface (no window, no desktop).
  • Who manages them? Supervised and controlled by the Service Control Manager (SCM) (services.exe).
  • When do they run? Boot automatically at machine startup, before any user even logs in!
  • Privilege Level: Usually runs under NT AUTHORITY\SYSTEM (local God mode)!
  • Real-world Examples: WinDefend (Defender Antivirus), wuauserv (Windows Update), Spooler (Print Spooler).
🏢 Mental Model: Like a skyscraper's electrical generators and water pumps in the basement — running 24/7 silently even when the offices are empty.
2. The Windows Registry Central Database
  • What is it? A centralized hierarchical database storing all OS, driver, hardware, software, and user configurations.
  • Linux vs. Windows: Replaces thousands of scattered Linux /etc/*.conf text files with one master database!
  • Hierarchy: Hives → Keys (like folders) → Values (Name, Type, Data).
  • HKLM (Local Machine): Global system settings for all users (Writing requires Administrator / UAC).
  • HKCU (Current User): Settings specific to the logged-in user (Standard user can write freely!).
🧬 Mental Model: The central DNA & master rulebook of Windows — every time the OS or an app does anything, it looks up the Registry first.
🔗 The Persistence Connection: Attackers abuse Services to gain SYSTEM privilege and survive reboots, and abuse Registry Run Keys (in HKCU or HKLM) to auto-launch malware whenever a user logs in!
Core Windows Engines

Services & The Registry: Threat Persistence Auditing

Now that you understand Services & Registry, here is how malware establishes persistence and how to audit it:

Windows Services (Background Workers)

# CMD service query:

sc query state= all

# PowerShell service auditing:

Get-Service | Where-Object Status -eq 'Running'

# Start / Stop / Restart:

Restart-Service -Name Spooler

Security Risk: Services run as NT AUTHORITY\SYSTEM (local God mode)!

Registry Persistence (Run Keys)

# Browse the Registry like a hard drive (PSDrive!):

cd HKCU:\Software; dir

# Audit user startup persistence keys:

Get-ItemProperty 'HKCU:\Software\Microsoft\Windows\CurrentVersion\Run'

# Audit system-wide machine startup keys:

Get-ItemProperty 'HKLM:\Software\Microsoft\Windows\CurrentVersion\Run'

📌 Persistence Forensics: The ...\CurrentVersion\Run and RunOnce registry keys are the single most common startup locations abused by malware to survive reboots.
